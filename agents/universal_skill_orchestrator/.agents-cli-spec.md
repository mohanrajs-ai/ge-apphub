# Agent Specification: Universal Enterprise Skill Orchestrator (`universal-skill-agent`)

## 1. Core Purpose & Problem Solved
Single deployable Google ADK Orchestrator Agent on Vertex AI Agent Runtime (`--deployment-target agent_runtime`) that dynamically loads governed **Parent Skills (`SKILL.md`)** and chains reusable **Sub-Skills** from the `geapphub` Published Skill Registry (`/api/v1/skills/registry`)—eliminating the need to deploy a new Reasoning Engine for every enterprise use case.

## 2. External APIs, Tools & Authentication
- **Tools:**
  - `load_skill_bundle(skill_name_or_id, engine_id, tool_context)`: Fetches the approved, environment-rendered (`{{ENGINE_ID}}`, `{{DATA_STORE_IDS}}`) Parent Skill instruction and sub-skill manifest from `geapphub`.
  - `execute_subskill(subskill_name_or_id, task_input, tool_context)`: Executes a child sub-skill via Gemini Enterprise `:streamAssist`.
- **Authentication & OAuth Passthrough:**
  - Registered in Gemini Enterprise via `agents-cli publish gemini-enterprise --authorization-id .../authorizations/ge-user-auth --mode adk`.
  - Extracts the calling GE user's forwarded OAuth 2.0 token from `callback_context.state` / `tool_context.state` so `:streamAssist` calls consume the calling user's GE seat quota and enforce their personal M365 (Outlook/SharePoint/Teams) ACLs.

## 3. Safety Constraints & Guardrails
- Only executes skills that have passed the 6-Stage `geapphub` Governance Factory (`PUBLISHED` state) and are distributed to the target `engine_id`.
- Never bypasses per-user OAuth token boundaries when querying enterprise connectors.

## 4. `agents-cli` Target Configuration
- **Template:** `adk` (built-in A2A protocol)
- **Deployment Target:** `agent_runtime`
- **Guidance File:** `GEMINI.md`
- **Publish Target:** `agents-cli publish gemini-enterprise --mode adk` + `v1alpha` `PATCH` (`defaultPinned: true`, `starterPrompts`)
